# Подготовка деплоя на Beget

Workflow `.github/workflows/deploy-beget.yml` собирает сайт при каждом push в
`main`. Загрузка на Beget заблокирована, пока repository variable
`BEGET_DEPLOY_ENABLED` не получит значение `true`.

## Рекомендуемая учётная запись Beget

Создайте отдельный FTP-аккаунт только для сайта `chestny-ai.ru` и ограничьте его
домашнюю директорию папкой сайта `public_html`. Тогда удалённый путь в workflow —
`/`, то есть корень этой ограниченной учётной записи.

Предпочтительный протокол — SFTP. Для него в панели Beget необходимо включить
SSH-доступ у созданного FTP-аккаунта. Если SSH/SFTP недоступен, используйте FTPS
с обязательным TLS. Незашифрованный FTP workflow намеренно не принимает.

Для SFTP также запросите у Beget проверенную строку публичного SSH host key в
формате `known_hosts` и сохраните её как repository variable `SFTP_KNOWN_HOSTS`.
Это не секрет, но она нужна для защиты от подключения к подменённому серверу.

## GitHub Secrets

В `Settings → Secrets and variables → Actions` добавьте ровно три секрета:

- `FTP_SERVER`: `sftp://ИМЯ_СЕРВЕРА:22` либо `ftps://ИМЯ_СЕРВЕРА:21`;
- `FTP_USERNAME`: логин отдельного FTP-аккаунта Beget;
- `FTP_PASSWORD`: пароль этого аккаунта.

Имя сервера нужно скопировать из панели Beget, не подменяя его доменом сайта.

## Разрешение первого деплоя

До отдельного разрешения не создавайте repository variable
`BEGET_DEPLOY_ENABLED=true`. При желании дополнительного ручного контроля
создайте GitHub Environment `beget-production` и включите required reviewers.

После разрешения деплоя workflow загрузит содержимое `dist/` в `/`. Существующие
лишние файлы на сервере автоматически не удаляются: загрузка обновляет и добавляет
файлы, чтобы первый запуск не уничтожил неизвестное содержимое хостинга.
