# SKILL: landing-builder

Создаёт одностраничные сайты (лендинги) на фреймворке Astro по запросу пользователя.

## Когда применять

Пользователь просит:

- «сделай лендинг»  
- «собери сайт-визитку»  
- «сделай одностраничный сайт»  
- «нужен лендинг для \[ниша\]»

## Что делает скилл

1. Создаёт новый проект Astro (если его нет)  
2. Формирует структуру лендинга из стандартных секций  
3. Добавляет базовую стилизацию (чистый современный вид, не «учебная заготовка»)  
4. Наполняет секции контентом под нишу пользователя  
5. Настраивает адаптив под мобильные устройства  
6. Запускает локальный сервер для предпросмотра

## Стандартная структура лендинга

Лендинг собирается из следующих секций (используй их все, если пользователь не указал иное):

1\. Header (шапка)

   \- Логотип / название

   \- Навигация (якоря по секциям)

   \- Кнопка CTA в шапке

2\. Hero (главный экран)

   \- Заголовок (оффер: что предлагаем)

   \- Подзаголовок (раскрывает оффер)

   \- Кнопка CTA (главное действие)

   \- Визуальный элемент (изображение / плейсхолдер)

3\. Benefits / Услуги (что предлагаем)

   \- 3-6 карточек с услугами или преимуществами

   \- Иконка \+ заголовок \+ описание для каждой

4\. About / О компании или эксперте

   \- Текстовый блок

   \- Фото / плейсхолдер

5\. Process / Как мы работаем (этапы)

   \- 3-5 шагов с номерами

6\. Testimonials / Отзывы (опционально)

   \- 2-3 отзыва

   \- Имя \+ текст \+ фото/плейсхолдер

7\. FAQ / Частые вопросы (опционально)

   \- 3-5 вопросов с раскрытием

8\. Contact / Контакты \+ CTA

   \- Кнопка связи (Telegram / WhatsApp / email / форма)

   \- Контактные данные

9\. Footer (подвал)

   \- Копирайт

   \- Соцсети

   \- Повтор навигации

### Правила кода

1. **Перед началом работы — проверь Node.js.** Выполни `node -v`. Если команда не выполняется (Node.js не установлен) — остановись и сообщи пользователю: «Установите Node.js LTS с сайта [https://nodejs.org](https://nodejs.org), затем перезапустите Codex». Без Node.js Astro не соберётся.  
     
2. **Astro v5+** — используй `npm create astro@latest -- --template minimal --no-install --no-git --yes` для нового проекта. Флаг `--yes` обязателен — без него Astro задаст интерактивные вопросы в терминале и Codex зависнет, ожидая ответа. Шаблон `minimal` — пустой, без лишнего. Затем установи зависимости: `npm install`.  
     
3. **Важно про шаблон minimal.** Этот шаблон максимально пустой — в нём нет ни `Layout.astro`, ни `global.css`. Ты должен СОЗДАТЬ ИХ САМ:  
     
   - `src/layouts/Layout.astro` — ОБЯЗАТЕЛЬНО с тегом `<slot />` внутри `<body>`. Без `<slot />` секции лендинга не отобразятся — будет белый экран.  
   - `src/styles/global.css` — глобальные токены (цвета, шрифты, отступы). ОБЯЗАТЕЛЬНО импортируй его в Layout.astro через `import '../styles/global.css';` в frontmatter.  
   - `src/pages/index.astro` — главный файл, куда импортируются все секции.

   

4. **Импорты — строго с двумя точками** (относительные пути из `pages/` в `components/` и `layouts/`):  
     
   \---  
     
   import Layout from '../layouts/Layout.astro';          // НЕ './layouts/...'  
     
   import Header from '../components/Header.astro';        // НЕ './components/...'  
     
   import Hero from '../components/Hero.astro';  
     
   // и т.д.  
     
   \---  
     
   Если написать с одной точкой (`./components/...`) — будет ошибка «модуль не найден».  
     
5. **Layout.astro — каркас с .** Пример правильной структуры:  
     
   \---  
     
   import '../styles/global.css';  
     
   \---  
     
   \<\!DOCTYPE html\>  
     
   \<html lang="ru"\>  
     
   \<head\>  
     
     \<meta charset="utf-8" /\>  
     
     \<meta name="viewport" content="width=device-width, initial-scale=1" /\>  
     
     \<title\>{Astro.props.title}\</title\>  
     
     \<\!-- Шрифты подключай здесь (см. правило про шрифты ниже) \--\>  
     
   \</head\>  
     
   \<body\>  
     
     \<slot /\>   \<\!-- ОБЯЗАТЕЛЬНО. Сюда вставятся секции из index.astro \--\>  
     
   \</body\>  
     
   \</html\>  
     
6. **TypeScript — строго No.** Если установщик спрашивает про TypeScript — отвечай отрицательно. Новичкам строгая типизация только мешает (лишние ошибки).  
     
7. **Каждая секция — отдельный компонент** в `src/components/`. Не клади весь лендинг в один файл.  
     
8. **Компоненты без клиентского JS** по умолчанию (Astro Islands). Избегай React/Vue, если можно обойтись чистым HTML+CSS. Islands — только для FAQ-аккордеона или мобильного меню, если нужно.  
     
9. **Inline `<script>`** для простой интерактивности (мобильное меню, smooth scroll, аккордеон FAQ) — прямо в компонентах Astro. Не тянуть фреймворки.  
     
10. **Стили — внутри компонентов** в теге `<style>`, либо в `global.css` для базовых токенов (цвета, шрифты). Не используй Tailwind, если пользователь явно не попросил — чистый CSS быстрее и понятнее для новичка.  
      
11. **Адаптив — обязательно.** Mobile-first. Используй `clamp()` для шрифтов, `@media` для сеток. Проверь что на 375px (iPhone SE) всё читаемо.  
      
12. **Изображения — плейсхолдеры.** Используй `<img>` с placeholder (например, `https://placehold.co/600x400`) или SVG-заглушку. Не ищи реальные фото — пользователь заменит сам.

### Шрифты

Подключай красивые шрифты с Google Fonts (пользователи работают через VPN, поэтому шрифты загрузятся). **Обязательно добавляй системный фолбэк** на случай если шрифт не загрузится:

\<link href="https://fonts.googleapis.com/css2?family=Manrope:wght@400;600;700\&display=swap" rel="stylesheet"\>

:root {

  \--font-heading: 'Manrope', 'Segoe UI', system-ui, \-apple-system, sans-serif;

  \--font-body: 'Manrope', 'Segoe UI', system-ui, \-apple-system, sans-serif;

}

Рекомендуемые пары с Google Fonts:

- Заголовки: Montserrat / Manrope / Plus Jakarta Sans  
- Текст: Inter / Manrope  
- Фолбэк всегда: 'Segoe UI', system-ui, \-apple-system, sans-serif

### Дизайн-правила (чтобы не было «учебной заготовки»)

1. **Не используй дефолтные цвета браузера** (синие ссылки, чёрный Times New Roman). Задай палитру в CSS-переменных в `global.css`:  
     
   :root {  
     
     \--color-bg: \#ffffff;  
     
     \--color-text: \#1a1a2e;  
     
     \--color-primary: \#6366f1;  /\* или подбери под нишу \*/  
     
     \--color-muted: \#6b7280;  
     
     \--spacing-section: clamp(3rem, 8vw, 6rem);  
     
     \--container: 1200px;  
     
     \--font-heading: 'Manrope', 'Segoe UI', system-ui, \-apple-system, sans-serif;  
     
     \--font-body: 'Manrope', 'Segoe UI', system-ui, \-apple-system, sans-serif;  
     
   }  
     
   body {  
     
     font-family: var(--font-body);  
     
     color: var(--color-text);  
     
     background: var(--color-bg);  
     
     margin: 0;  
     
     line-height: 1.6;  
     
   }  
     
2. **Подбирай \--color-primary под нишу** (спроси пользователя или предложи):  
     
   - Медицина / здоровье → мягкий синий/зелёный (\#0ea5e9, \#10b981)  
   - Красота / мода → розовый/фиолетовый (\#ec4899, \#8b5cf6)  
   - Финансы / юриспруденция → тёмно-синий/бордо (\#1e3a8a, \#991b1b)  
   - IT / технологии → индиго/бирюзовый (\#6366f1, \#14b8a6)  
   - Питание / кафе → оранжевый/коричневый (\#f97316, \#92400e)

   

3. **Отступы и воздух** — не лепи элементы друг к другу. `padding` секций не меньше `clamp(3rem, 8vw, 6rem)`. Внутри карточек — `clamp(1.5rem, 3vw, 2rem)`.  
     
4. **Тени и скругления** — добавляй умеренно, это придаёт «дорогой» вид:  
     
   box-shadow: 0 4px 6px \-1px rgba(0,0,0,0.1);  
     
   border-radius: 12px;  
     
5. **Кнопки** — чёткие, с hover-эффектом:  
     
   .btn-primary {  
     
     background: var(--color-primary);  
     
     color: white;  
     
     padding: 0.875rem 2rem;  
     
     border-radius: 8px;  
     
     font-weight: 600;  
     
     transition: transform 0.2s, box-shadow 0.2s;  
     
     display: inline-block;  
     
     text-decoration: none;  
     
   }  
     
   .btn-primary:hover {  
     
     transform: translateY(-2px);  
     
   }

### Контент

1. **Спроси нишу и оффер** до сборки, если пользователь их не дал. Не генерируй абстрактный «Добро пожаловать на наш сайт».  
2. **Тексты — конкретные, под нишу.** Если пользователь дал мало вводных — сгенерируй разумные тексты, но пометь их как заготовки для замены в HTML-комментарии:  
     
   \<\!-- TODO: Замените этот текст на реальный \--\>  
     
3. **Кнопка связи** — спроси какой канал (Telegram / WhatsApp / email / форма). Если не указано — поставь ссылку на Telegram как самый универсальный в РФ:  
     
   \<a href="https://t.me/username" class="btn-primary"\>Написать в Telegram\</a\>

## Как собирать (порядок действий)

Когда пользователь просит собрать лендинг:

### Шаг 1\. Уточнить вводные (если не даны)

Спроси:

1. Какая ниша / для кого сайт?  
2. Какой основной оффер (что предлагаем)?  
3. Какой канал связи для кнопки (Telegram/WhatsApp/email)?  
4. Есть ли предпочтения по цветам / стилю?

### Шаг 2\. Проверить Node.js

Выполни `node -v`. Если не работает — сообщи пользователю установить Node.js LTS с [https://nodejs.org](https://nodejs.org). Без Node.js продолжать нельзя.

### Шаг 3\. Создать проект (если нет)

Если в текущей папке уже есть файлы Astro (`astro.config.mjs`) — пропусти этот шаг, работай в существующем проекте.

Если папка пустая (или почти пустая, только SKILL.md) — создай Astro-проект:

npm create astro@latest \-- \--template minimal \--no-install \--no-git \--yes

Флаг `--yes` — чтобы Astro не задал интерактивные вопросы и не завис. Затем установи зависимости: `npm install`

> **Важно:** если Astro ругается «папка не пустая» из\-за файла SKILL.md — попроси пользователя создать новую подпапку (например, `site`) и создай проект там. Либо временно перемести SKILL.md.

### Шаг 4\. Создать базовую структуру (если её нет)

1. **`src/layouts/Layout.astro`** — каркас с `<head>`, импортом `global.css` и **обязательным `<slot />`** в `<body>`. (См. пример выше в правиле 5.)  
2. **`src/styles/global.css`** — CSS-переменные (цвета, шрифты, отступы). Базовые стили `body`.  
3. **`src/components/`** — создай 9 компонентов по списку секций (Header, Hero, Benefits, About, Process, Testimonials, FAQ, Contact, Footer).  
4. **`src/pages/index.astro`** — импортируй Layout и все компоненты (с путями `'../...'`, две точки\!), собери страницу.

### Шаг 5\. Запустить локально

npm run dev

Сообщи пользователю ссылку (обычно `http://localhost:4321`). Дождись, пока в терминале появится сообщение что сервер запущен.

## Чего НЕ делать

- ❌ Не использовать Tailwind CSS по умолчанию (только если пользователь явно попросил)  
- ❌ Не тянуть React/Vue/Svelte для статичного контента  
- ❌ Не использовать тяжёлые JS-фреймворки для анимаций (лучше CSS-transitions)  
- ❌ Не клепать дефолтный фиолетовый градиент «как у всех AI» — подбирай цвет под нишу  
- ❌ Не генерировать лорем-ипсум — пиши конкретные тексты под нишу, с пометкой TODO для замены  
- ❌ Не забывать про мобилки — mobile-first обязательно  
- ❌ Не публиковать на хостинг — это отдельный скилл `deploy`  
- ❌ Не начинать сборку без проверки Node.js  
- ❌ Не забывать `<slot />` в Layout.astro — без него белый экран  
- ❌ Не использовать импорты с одной точкой (`./components/...`) — только с двумя (`../components/...`)  
- ❌ Не подключать шрифты без системного фолбэка — если Google Fonts не загрузится, должен быть запасной вариант (Segoe UI, system-ui)
