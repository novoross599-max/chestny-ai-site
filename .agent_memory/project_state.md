# Состояние проекта

- Создан одностраничный сайт «Заработай с ИИ: Честный Дневник» на Astro 5.18.2.
- Реализованы отдельные компоненты: шапка, главный экран, о проекте, темы обучения, результаты, процесс, материалы, Plaan Академия, Telegram, FAQ, контакты и подвал.
- Добавлены адаптивные стили, мобильное меню, нативный FAQ, круглая фотография автора и базовая доступность.
- В шапке используется `public/images/author.jpg`: аватар сохранён в компактном размере 42×42 px, кадрируется через `object-fit: cover` и `object-position: 50% 42%` без искажения пропорций.
- Цветовая система унифицирована: светлый фон, фирменный тёмно-зелёный и охристый CTA-акцент; основной текст на светлом фоне сделан почти чёрным, на зелёном — белым.
- Заголовки используют serif, основной текст — локально размещённый Manrope с системным sans-serif fallback; размеры адаптивны. Внешние подключения и `preconnect` к Google Fonts удалены.
- Кнопки чтения дневника и перехода в канал ведут на Telegram-блог `https://t.me/AI_Dnevnik_K` (`@AI_Dnevnik_K`); личный Telegram-контакт в разделе «Мои контакты» ведёт отдельно на `https://t.me/Constant2026` (`@Constant2026`). Все внешние Telegram-ссылки открываются в новой вкладке с `rel="noopener noreferrer"`.
- Раздел «Связаться со мной» юридически подготовлен к будущему сбору данных: форма сообщения содержит только имя, Email или Telegram и сообщение; подписка — только Email. Для каждой формы указана отдельная цель обработки и добавлен собственный пустой по умолчанию checkbox согласия с прямыми юридическими ссылками.
- Отправка обращения и подписка полностью отключены: кнопки `disabled`, формы не имеют `action`/`method`, попытка submit дополнительно блокируется на клиенте; данные не передаются и не сохраняются.
- Созданы отдельные статические страницы-заготовки `/privacy/`, `/personal-data-consent/` и `/newsletter-consent/`. На них отсутствующие реквизиты оператора и технические сведения показаны как заметные TODO, а документы явно помечены как не готовые к публикации.
- В футер добавлен компактный раздел «Правовая информация» со ссылками на все три страницы.
- В блоке Plaan Академии размещены две спокойные карточки бесплатных практикумов с реальными партнёрскими ссылками и полным пояснением условий. Ссылки открываются в новой вкладке с `rel="noopener noreferrer sponsored"`.
- Astro Dev Toolbar отключён через `devToolbar: { enabled: false }`.
- Зависимости установлены, `npm run build` успешно формирует четыре статические страницы в `dist/`: главную и три юридические.
- Главная и юридические страницы проверены на ширинах 1440 px и 375 px: горизонтального переполнения нет, формы и футер корректно перестраиваются, юридические ссылки доступны.
- Отображение обновлённой шапки проверено на ширинах 1440 px и 375 px: размеры аватара и высота шапки сохранены, мобильное меню работает без горизонтального переполнения.
- Локальный сервер предпросмотра запущен на `http://127.0.0.1:4321/` и отвечает `200 OK`.
- Сайт не публиковался в интернет.
- Проект подготовлен как Git-репозиторий с основной веткой `main` и связан с новым GitHub-репозиторием `https://github.com/novoross599-max/chestny-ai-site.git` через remote `origin`.
- `.gitignore` исключает зависимости, результаты сборки, `.env`-файлы, распространённые форматы ключей и локальные файлы инструментов; проверка исходников не выявила явных паролей, токенов, приватных ключей или FTP/SFTP-реквизитов.
- Локально подготовлен GitHub Actions workflow сборки и безопасной загрузки `dist/` на Beget через SFTP либо FTPS. Деплой заблокирован переменной `BEGET_DEPLOY_ENABLED` и не коммитился, не отправлялся в GitHub и не запускался.

## Следующий этап

После проверки локального подключения Manrope дождаться отдельного разрешения пользователя перед публикацией. До публикации также подтвердить в панели Beget протокол, имя сервера и домашний каталог отдельного FTP-аккаунта для `chestny-ai.ru`, добавить три GitHub Secrets и только после отдельного разрешения включить `BEGET_DEPLOY_ENABLED=true`. Предоставить реальные реквизиты оператора, утвердить юридические документы с профильным специалистом и выбрать российское решение для обработки и хранения данных. Хостинг и настройки Beget не изменялись.
