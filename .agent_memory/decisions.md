# Важные решения

## Постоянная память проекта

- Решение: хранить состояние, решения, ошибки и постоянные требования в отдельных файлах каталога `.agent_memory`.
- Причина: это позволяет начинать каждую новую задачу с актуального контекста и обновлять только относящуюся к ней часть памяти.

## Дизайн лендинга

- Решение: использовать тёплый редакционный стиль с бумажным фоном, глубоким зелёным цветом и охристым акцентом.
- Причина: спокойная палитра поддерживает доверие и намеренно избегает шаблонного фиолетового AI-дизайна.
- Решение: ограничить типографику системным serif для заголовков и Manrope с системным sans-serif fallback для основного текста.
- Причина: это улучшает иерархию, читабельность и сохраняет не более двух семейств шрифтов.

## Техническая реализация

- Решение: собрать сайт на чистом Astro с CSS и минимальным inline JavaScript только для мобильного меню.
- Причина: это соответствует `landing-builder`, обеспечивает быструю загрузку и не добавляет React, Vue, Tailwind или тяжёлые библиотеки.
- Решение: формы оставлять с отключёнными кнопками до подключения backend.
- Причина: временные элементы явно обозначены и не создают ложного впечатления успешной отправки данных.
- Решение: юридические документы реализовать как отдельные статические страницы с общей визуальной оболочкой и явно выделенными техническими TODO вместо вымышленных реквизитов.
- Причина: сайт получает готовую навигационную и интерфейсную основу, но заготовки нельзя ошибочно принять за завершённые юридические документы.
- Решение: согласия формы обращения и подписки разделить, оставить пустыми по умолчанию и постоянно блокировать submit до подключения российского решения обработки и хранения.
- Причина: цели обработки различаются, а текущий статический сайт не должен передавать или сохранять персональные данные даже при нажатии Enter.
- Решение: фотографию автора в шапке кадрировать в существующем размере 42×42 px через `object-fit: cover` и `object-position: 50% 42%`.
- Причина: такое кадрирование сохраняет пропорции портрета, удерживает лицо по центру круглого аватара и не меняет компактность шапки.
- Решение: разделять Telegram-блог `@AI_Dnevnik_K` и личный контакт автора `@Constant2026` по назначению ссылок.
- Причина: кнопки чтения ведут только в канал, а блок «Мои контакты» — только в личный диалог с автором.
- Решение: показывать предложения Plaan Академии двумя нейтральными карточками и размещать под ними полное раскрытие партнёрских условий.
- Причина: так практикумы различимы, а бесплатное участие, возможное платное продолжение и вознаграждение автора описаны прозрачно и без агрессивной рекламы.

## Контроль версий

- Решение: использовать ветку `main` и remote `origin`, указывающий на `https://github.com/novoross599-max/chestny-ai-site.git`.
- Причина: это новый пустой репозиторий, явно указанный пользователем; до инициализации подтверждено, что локальный проект не имел Git-метаданных и существующих remotes.
